# OSS 检修

## 事实边界

- Bucket 名称、OSS 实例名称、组织、资源集、账号、容量、权限和环境只能取自用户需求或已确认字段。
- RAG 中的系统名、Bucket、组织、资源集和容量均为历史样例，不得写入本次方案。
- 缺少事实参数时写“待实施前确认”，不得根据历史方案猜测。

## 资源参数表

- 创建 OSS：OSS 实例名称、Bucket 名称、容量阈值、读写权限、组织、资源集、环境。
- 容量扩容：OSS 实例名称、Bucket 名称、当前容量阈值、目标容量阈值、扩容大小、读写权限、组织、资源集、环境。
- 多个 Bucket 必须每个占一行，并在实施步骤中逐个执行、逐个核对，不能用“其他实例同上”代替操作对象。

## 实施步骤

### 创建 OSS

1. 登录对应网络环境的 ASCM 平台，选择“对象存储 OSS”，进入用户指定的组织和资源集。
2. 打开 Bucket 列表并执行创建，逐项填写用户提供的 Bucket 名称、容量阈值和读写权限。
3. 提交前由复核人核对网络环境、组织、资源集、Bucket 名称、容量和权限；提交后等待平台返回成功结果。
4. 检查 Bucket 状态、容量阈值和读写权限，并联系项目组验证访问链路；保留创建结果和验证截图。

### OSS 容量扩容

1. 登录对应网络环境的 ASCM 平台，选择“对象存储 OSS”，进入用户指定的组织和资源集。
2. 在 Bucket 列表按用户提供的 OSS 实例名称或 Bucket 名称定位对象，进入实例详情的“基础设置”。
3. 在“设置容量阈值”模块记录并截图当前容量阈值、Bucket 状态和读写权限。
4. 点击“设置”，将当前容量阈值修改为目标容量阈值；提交前核对扩容大小等于目标值减当前值。
5. 由复核人核对 Bucket、组织、资源集、当前容量、目标容量和权限后点击“提交”，等待平台返回成功结果。
6. 多个 Bucket 按参数表逐个执行并记录结果，不得遗漏或合并对象。
7. 扩容后逐个核对目标容量阈值、Bucket 状态和读写权限，检查监控与告警，并联系项目组验证业务读写；保留检修后截图。

禁止使用“按需设置”“进行检查”“完成后验证”等无法复核的空泛表述。

## 风险与回滚

- 创建和扩容通常不涉及业务重启，但必须以用户需求为准，不得擅自承诺无影响。
- 需覆盖操作对象错误、容量值错误、权限误改、组织或资源集选择错误、提交后未验证等风险。
- 创建类回滚：删除本次新建且尚未承载业务数据的 Bucket；删除前必须再次确认对象和业务使用状态。
- 扩容类先确认平台是否支持容量阈值调小。支持时恢复参数表中的原容量阈值；不支持时明确写“平台不支持缩容，不执行配置回退”，停止继续操作并升级人工处置，严禁无依据承诺可回退。
- 回滚后必须复核 Bucket 状态、容量阈值、读写权限和业务访问，并截图留痕。

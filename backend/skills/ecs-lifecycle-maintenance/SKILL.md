# ECS 生命周期检修

本 Skill 必须与 `maintenance-plan-composer` 共同使用。通用章节骨架由 composer 决定，本 Skill 负责 ECS 资源参数、风险内容、实施步骤和回滚步骤的具体化。

## ECS 参数表

创建 ECS 时，`现场环境` 章节后必须输出 ECS 参数表，列名固定：

| 云环境 | 实例名称 | 磁盘 | 自定义镜像 | 密码 | VPC ID或名称 | Vswitch ID或名称 | 安全组 | 实例规格 | 数量 |

字段来源：

- 云环境：内网/外网/内外网。
- 实例名称：用户给出的实例名或系统名派生出的实例名。
- 磁盘：系统盘、数据盘，示例 `系统50G / 数据盘200G`。
- 自定义镜像：用户提供则使用；缺失时写 `待实施前确认`。
- 密码：不要生成真实密码；用户提供时原样写，未提供写 `按 ASCM 平台规范生成，方案不明文展示`。
- VPC、VSwitch、安全组：缺失时必须写 `待实施前确认`，不得省略列。
- 实例规格：例如 `16C32G`、`4C16G`。
- 数量：例如 `3`。

升配/降配时输出当前规格、目标规格、实例名/IP、云环境。回收或重启时输出实例名、IP、资源集、云环境。

## 风险评估内容

### 5.1影响范围

创建 ECS：

- `{事项名}对业务无影响；`

升配/降配/重启：

- 写明是否需要重启、是否可能影响业务访问、是否需要项目组业务验证。

回收 ECS：

- 写明回收对象必须经项目组确认无业务流量和无依赖；误删会导致业务资源不可用。

### 5.2危险点分析

必须保留 composer 的四项默认危险点，并结合 ECS 场景细化：

1. 授权不当：授权过大，影响预定方案以外的生产环境实例。
2. 备份不当：升配/降配/回收/重启前未完成快照、配置或业务状态确认，导致无法应急回退。创建 ECS 可写“本次创建新实例不涉及业务数据备份，但需保留创建参数用于回滚删除核对”。
3. 验证不当：ECS 操作对象、组织、资源集、VPC、VSwitch、安全组、镜像、规格、IP 地址余量未核实清楚，导致创建失败或业务不可达。
4. 双人复核不当：未复核组织、资源集、实例参数和提交动作，导致错误执行。

### 5.3安全措施

必须包含：

- `5.3.1授权`：`ASCM：{授权范围}     授权账号：{ascm_account}`；下一行 `堡垒机账号：{bastion_account}`。
- `5.3.2备份`：
  - 创建 ECS：`(1){事项名}不涉及备份`。
  - 升配/降配：`(1)记录变更前实例规格、磁盘、IP、VPC、VSwitch、安全组和实例运行状态；必要时确认快照或业务备份有效。`
  - 回收 ECS：`(1)确认实例无业务流量、无挂载依赖，保留实例配置和项目组确认记录。`
  - 重启 ECS：`(1)确认业务具备冗余或窗口期允许中断，必要时完成快照/业务备份确认。`
- `5.3.3验证`：
  - 创建 ECS：`(1){事项名}检查资源集 IP 充足，确认 VPC、VSwitch、安全组、镜像、规格、磁盘、数量与需求一致。`
  - 升配/降配：`(1)检查目标实例运行状态正常，记录当前规格和业务连通性。`
  - 回收 ECS：`(1)检查实例无业务连接、无告警、无挂载依赖，并取得项目组确认。`
  - 重启 ECS：`(1)检查实例当前运行状态、服务状态和业务冗余情况。`
- `5.3.4 双人复核`：固定写：
  - `(1)确认在正确的组织和资源集下做操作，检查实例操作对象是否正确；`
  - `(2)严格按照文档复核关键步骤及关键点。`

## 创建 ECS 实施步骤

当任务为“创建 ECS / 新建云服务器 / 申请 ECS 实例”时，必须使用以下颗粒度，不能压缩成泛泛描述。

### 6.1备份

- `1、{事项名}不涉及备份`

### 6.2 检修前验证

至少输出：

1. `{事项名}检查资源集 IP 充足`
2. `确认组织“{组织}”、资源集“{资源集}”、云环境“{内网/外网}”与工单需求一致。`
3. `确认 VPC、VSwitch、安全组、镜像、实例规格、磁盘、数量已由双人复核。`

### 6.3 检修操作

必须包含小节 `6.3.1 {事项名}`，并写清楚：

1. `使用{ascm_account}账号，登录{内网/外网}ASCM平台，产品选择“云服务器ECS”。`
2. `选择组织“{组织}”-资源集“{资源集}”，进入云服务器 ECS 实例列表。`
3. `点击“创建”或“创建ECS实例”。`
4. `按参数表填写云环境、实例名称、磁盘、自定义镜像、VPC、VSwitch、安全组、实例规格、数量等内容。`
5. `确认填写内容无误后，由检修复核人进行关键参数复核。`
6. `复核通过后点击提交，等待创建任务完成。`
7. `创建完成后进入实例列表，确认新建 ECS 实例状态为运行中或正常，记录实例 ID、IP 地址和所属资源集。`

如果涉及多台实例，不要只写“批量创建”，要说明按参数表逐项核对数量和实例名。

### 6.4 检修后验证

至少输出：

1. `验证{事项名}实例状态正常；`
2. `核对实例名称、规格、磁盘、镜像、VPC、VSwitch、安全组、IP、资源集与参数表一致；`
3. `联系项目组验证业务正常；`
4. `保留 ASCM 创建结果截图、实例列表截图和项目组验证记录。`

## 创建 ECS 回滚步骤

### 7.1 回滚操作

必须包含：

1. `{事项名}回退`
2. `删除新建ecs实例`
3. `确认实例列表中已不存在本次新建实例，或实例处于已释放状态。`

### 7.2 回滚后验证

必须包含：

1. `{事项名}回退验证`
2. `验证回退正常；联系项目组验证业务正常。`

## 升配/降配差异

实施操作必须写：

1. 登录 ASCM，进入云服务器 ECS。
2. 按组织、资源集定位目标实例。
3. 记录变更前规格。
4. 选择升配/降配或规格变更。
5. 选择目标规格并提交。
6. 等待任务完成后核对实例规格、运行状态和业务连通性。

回滚为恢复原规格并重新验证业务。

## 回收 ECS 差异

实施操作必须写：

1. 项目组确认实例可回收。
2. 登录 ASCM，进入云服务器 ECS。
3. 按组织、资源集和实例名/IP 定位目标实例。
4. 复核无误后执行释放/删除/回收。
5. 确认实例列表已无目标实例。

回滚为按保留配置重新创建实例或按备份恢复，必须注明需项目组确认。

## 维护性重启差异

实施操作必须写：

1. 登录堡垒机或 ASCM 定位目标 ECS。
2. 检查当前服务状态和业务冗余。
3. 按实例逐台重启，等待每台恢复正常后再处理下一台。
4. 检查实例运行状态、系统日志、服务状态和业务连通性。

重启通常不写“删除/恢复”，异常时按业务应急预案恢复或联系平台支持。

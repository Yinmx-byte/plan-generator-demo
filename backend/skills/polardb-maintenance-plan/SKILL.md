# PolarDB 检修 Skill

## 适用场景

- 创建 PolarDB 实例（含只读实例）。
- 回收/释放空闲 PolarDB 实例（含只读实例）。
- PolarDB 磁盘扩容。
- PolarDB 实例升配/降配/规格变更。
- PolarDB 读写分离链路切换。
- PolarDB 高权限账号回收。
- 以上场景的混合操作（如同一检修窗口内同时执行账号回收和升配）。

## 文档结构要求

生成 JSON 时必须严格遵循以下七章结构，编号和层级与参考方案一致。

章节概览：

```
一、背景
二、检修类型（checkbox_group）
三、现场环境
四、实施计划（4.1 检修窗口 / 4.2 实施人员）
五、风险评估（5.1影响范围 / 5.2危险点分析 / 5.3安全措施 → 5.3.1授权 / 5.3.2备份 / 5.3.3验证 / 5.3.4双人复核）
六、实施步骤（6.1备份 / 6.2检修前验证 / 6.3检修操作 / 6.4检修后验证）
七、回滚步骤（7.1回滚操作 / 7.2回滚后验证）
```

文档开头输出标题（`{系统名}{动作}检修方案`），然后是部门名"云运营中心平台运维处"和当前日期。

## 各章节详细规则

### 一、背景

格式：先输出"背景"作为标题，下一段为具体内容。
- 单事项："{系统名}{动作}"。下一段可选："该事项项目组提报问题工单，需检修进行处理，实现问题工单闭环。"或"以上事项项目组提报问题工单，需检修进行处理，实现问题工单闭环。"
- 多事项：先给总标题（如"内网统一流程BPM系统ecs升配、内网纪检监察工作信息系统回收空闲polardb实例……等检修方案"），背景中用 `1）XX`、`2）XX` 逐条列出每个子事项。

### 二、检修类型

必须使用 `checkbox_group` 块，固定两行布局：

第一行选项：配置变更、组件升级、组件扩缩容
第二行选项：数据库变更（勾选✓）、日常维护（原硬件设备）（勾选✓）、其他 ____

所有 PolarDB 检修方案均勾选"数据库变更"和"日常维护（原硬件设备）"，不勾选"配置变更""组件升级""组件扩缩容"。

### 三、现场环境

使用 `paragraphs` 或 `key_values` 块，固定包含四个子项：

```
（1）内网环境/外网环境：{内网/外网/内、外网环境}
（2）实施地点：国网亦庄数据中心二期运维专区
（3）专有云版本：v3.16
（4）涉及的组件实例信息：
```

第（4）项下方紧接着输出：
- `1、{系统名}{动作}` 作为 numbered_list 首项
- `组织：{组织名}`
- `资源集：{资源集名}`
- 如有具体实例，追加"涉及{动作}实例："或"涉及{动作}polardb实例：
      {"type": "table", "headers": ["实例名称", "实例规格", "存储空间", "芯片架构", "数据库类型", "数据库版本", "VPC ID(名称)", "Vswitch ID(名称)", "白名单", "数量", "组织"], "rows": [
        ["系统名-polardb", "4c16g", "500GB", "通用(x86)", "MySQL", "8.0", "vpc10", "业务Vswitch", "内网白名单组", "1", "组织名"]
      ]},

实例信息表格列，按场景区分：

**创建/创建只读实例**（11 列）：

| 实例名称 | 实例规格 | 存储空间 | 芯片架构 | 数据库类型 | 数据库版本 | VPC ID(名称) | Vswitch ID(名称) | 白名单 | 数量 | 组织 |

**回收/升配/磁盘扩容/读写分离链路切换**（5 列）：

| 实例ID | 实例名称 | 规格 | 组织 | 资源集 |

- 实例ID 格式：`rm-xxx`（集群实例）或 `rr-xxx`（只读实例）。
- 规格格式：如 `4c16g500GB`（更常用 2c4g、4c8g 等简化格式）、`32c128g1000GB`、`64c512g3000GB`。
- 芯片架构：`通用(x86)`、`鲲鹏(ARM)`。
- 数据库类型：`MySQL`。
- 数据库版本：`8.0`、`5.7`。

### 四、实施计划

#### 4.1 检修窗口

使用 `table` 块，列：检修年份、检修开始时间、检修结束时间。

#### 4.2 实施人员

使用 `table` 块，列：角色、姓名。
角色固定五种：方案提供人、检修执行人、检修复核人、业务系统负责人、安全责任人。
"业务系统负责人"默认填"不涉及"。

### 五、风险评估

#### 5.1 影响范围

固定句式：`{系统名}{动作}对业务无影响；`

多事项时逐条编号：
```
1、{系统名}{动作}对业务无影响；
2、{系统名}{动作}对业务无影响；
```

#### 5.2 危险点分析

必须包含以下四类危险点，措辞固定：

```
（1）授权不当危险点：授权过大，导致操作影响预定方案以外的生产环境实例。
（2）备份不当危险点：检修前实例未进行备份或备份无效，导致操作失败后无法完成应急回退。
（3）验证不当危险点：{实例类型}操作对象，以及服务是否存在单点隐患未核实清楚，导致操作后出现业务影响。
（4）双人复核不当危险点：双人复核不仔细，导致操作错误执行而出现业务影响。
```

第（3）类中的 `{实例类型}` 根据本次操作填写，如"数据库""polardb""rds、ecs和k8s集群""ecs、PolarDB和k8s集群"等，参考方案中常用措辞。

#### 5.3 安全措施

##### 5.3.1 授权

固定格式：
```
ASCM：国网总部直属单位权限     授权账号：{ascm账号}
堡垒机账号：{堡垒机账号，多人用逗号分隔}
```

##### 5.3.2 备份

格式：`(1){系统名}{动作}检查备份正常`

或对于不涉及备份的操作（创建、创建只读、回收、回收只读）：`(1){系统名}{动作}不涉及备份`

**各场景规则**：
- 创建实例：**不涉及备份**（新建实例无存量数据需备份）
- 创建只读实例：**不涉及备份**
- 回收实例：不涉及备份
- 回收只读实例：不涉及备份
- 磁盘扩容：检查备份正常
- 实例升配：检查备份正常
- 读写分离链路切换：检查备份正常
- 高权限账号操作：检查备份正常

##### 5.3.3 验证

格式：`(1){系统名}{动作}检查实例运行正常`

各场景规则：
- 创建实例/创建只读实例：**检查资源集IP充足**（新建前需确认资源集有足够 IP）
- 回收实例/回收只读实例：检查实例运行正常
- 磁盘扩容/实例升配/读写分离链路切换/高权限账号操作：检查实例运行正常

##### 5.3.4 双人复核

固定两条：
```
(1)确认在正确的组织和资源集下做操作，检查实例操作对象是否正确；
(2)严格按照文档复核关键步骤及关键点。
```

### 六、实施步骤

#### 6.1 备份

格式：`1、{系统名}{动作}检查备份正常` 或 `1、{系统名}{动作}不涉及备份`

规则与 5.3.2 备份一致：
- 创建实例/创建只读实例/回收实例/回收只读实例 → "不涉及备份"
- 磁盘扩容/升配/读写分离切换/高权限账号 → "检查备份正常"

#### 6.2 检修前验证

格式：`1、{系统名}{动作}检查实例运行正常`

各场景规则与 5.3.3 验证一致：
- 创建实例/创建只读实例：`1、{系统名}{动作}检查资源集IP充足`
- 回收实例/回收只读实例/磁盘扩容/实例升配/读写分离链路切换/高权限账号操作：`1、{系统名}{动作}检查实例运行正常`

## 多事项混合方案规则

当一个检修窗口包含多个 PolarDB 事项（如同时有创建和回收），必须：
1. 标题概括所有事项。
2. 背景用 `1）` `2）` 逐条列出。
3. 影响范围、备份、验证、操作、检修后验证、回滚均按事项逐条编号。
4. 6.3 检修操作中每个事项独占一个 6.3.x 三级标题。
5. 每个事项的表格独立，不合并。

- 目标规格或磁盘容量

- 备份：检查备份正常
- 磁盘扩容回滚：不涉及回退
- 升配回滚：按照检修改回原配置

- 备份：检查备份正常
- 回滚：不涉及回退

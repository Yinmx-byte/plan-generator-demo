# Redis 实例检修方案生成

根据用户提供的检修关键信息，生成一份结构完整、可直接交付的 Redis 检修方案 **.docx 文件**。

## 工作流程

### 第一步：收集信息

从用户输入中提取以下信息。缺失必须项时主动询问，建议项缺失时使用默认值。

**必须信息：**
- 检修事项名称（如"内外网网上国网灰度和生产环境创建redis实例"）
- 操作类型：`创建` / `回收` / `升配` / `降配`
- 环境：`内网` / `外网` / `内外网`
- 组织名称、资源集名称
- Redis 实例详情（不同操作类型对应不同表格，见下方"操作类型差异指南"）
- 检修窗口：年份、开始时间、结束时间
- 实施人员：方案提供人、检修执行人、检修复核人、安全责任人
- ASCM 授权账号、堡垒机账号

**建议信息（缺失时使用默认值）：**
- 业务系统参与人（默认"不涉及"）
- 实施地点（默认"国网亦庄数据中心二期运维专区"）
- 专有云版本（默认"v3.16"）
- 日期（默认当天）
- 检修类型勾选（默认勾选"配置变更"和"数据库变更"）
- 业务影响描述（默认"对业务无影响"）
- 检修操作的具体步骤（默认使用下方"操作类型差异指南"中的标准步骤）
- 回滚操作的具体步骤（同上）

### 第二步：确认信息

将收集到的信息以简洁列表回显给用户确认。重点展示：
- 检修事项名称和操作类型
- 实例详情表格
- 检修窗口和人员
- 关键操作步骤概要

### 第三步：生成 .docx 文件

确认后，将收集的信息整理为 JSON 数据结构（见下方"输入数据结构"），然后运行脚本生成 .docx：

```bash
python <skill-path>/scripts/generate_plan.py --data /tmp/redis_plan_data.json --output <输出路径>.docx
```

生成后将文件路径告知用户。

文件命名规则：`V<版本号>-<检修事项名称>检修方案.docx`。版本号从 `output/versions.json` 读取，新标题从 V1.0 起，已有标题自动递增。所有生成的文档统一存放在 `output/` 目录下。

## 操作类型差异指南

### 实例详情表格

根据操作类型，`instances` 字段使用不同的列结构。

**创建实例：**

列：数据库名称, 数据库版本, 实例规格, 芯片架构, VPC ID或名称, Vswitch ID或名称, 密码, 数量, 环境

示例行：`["用户中心Redis", "Redis6.0", "16G集群版", "海光芯片", "交易系统专有VPC", "生产Vswitch", "******", "1", "外网"]`

**回收实例：**

列：实例ID, 实例名称, 实例规格, 环境

示例行：`["r-9ur48a42321eef24", "合规业务生产REDIS", "2G主从版", "内网"]`

> **注意：回收的实例信息在文档中以纯文本行展示（非表格）**，格式为 `实例ID  实例名称  实例规格`。多实例时按"内网""外网"环境分组，每组前加环境名称作为独立行。脚本已自动处理此逻辑，只需按列结构提供数据即可。

**升配/降配实例：**

列：实例名称, 实例ID, 当前规格, 目标规格, 环境

示例行（升配）：`["供应链运营中心生产REDIS", "r-9ur535772a1a4984", "4G主从版", "8G主从版", "内网"]`

示例行（降配）：`["E链国网生产Redis", "r-9ur56c40847a6064", "64G集群版", "32G集群版", "内网"]`

### 备份、验证、操作、回滚的默认值

| 维度 | 创建 | 回收 | 升配 | 降配 |
|------|------|------|------|------|
| 备份 (5.3.2/6.1) | 不涉及备份 | 不涉及备份 | 检查备份正常 | 检查备份正常 |
| 验证 (5.3.3/6.2) | 检查资源集IP充足 | 检查实例运行正常 | 检查实例运行正常 | 检查实例运行正常 |
| 操作 (6.3) | ASCM创建实例 | ASCM释放实例 | ASCM变更配置升级 | ASCM变更配置降级 |
| 回滚 (7.1) | 删除新建redis实例 | 回收实例不涉及回退 | 按照检修回退原实例 | 按照检修回退原实例 |

### 检修操作步骤指导

操作步骤由脚本按类型自动生成（自然段落，非编号列表）。用户可通过 `steps.operation` 自定义覆盖。

**创建** — ASCM 平台创建新 Redis 实例（3个自然段）：
```
使用账号{account}登陆外网云ASCM平台，产品选择"云数据库Redis"，选择组织"{org}"-资源集"{resource_set}"，点击"创建实例"。
按需选择芯片、数据库版本、架构类型、实例规格
网络类型选择专有网络，选择vpc和vswitch，输入实例名称、密码、创建数量，点击提交
```
6.3.1 小标题固定为 `创建redis实例`。

**回收** — ASCM 平台释放 Redis 实例（2个自然段）：
```
使用账号{account}登录ascm平台，进入云数据库Redis，组织选择"{org}"，资源集选择"{resource_set}"，进入rds实例：{instance_id} {instance_name}
点击释放实例，确认释放实例。等待任务完成。
```
6.3.1 小标题固定为 `回收redis实例`。

> 模板原文措辞请参考 `references/create-redis.md` 和 `references/recycle-redis.md`。

**升配** — ASCM 平台变更配置升级规格（3个自然段）：
```
使用账号{account}登陆内网云ASCM平台，产品选择"云数据库Redis"，选择组织"{org}"-资源集"{resource_set}"，点击进入指定Redis实例-实例信息，点击"变更配置"
按需选择架构类型和实例规格，点击提交
等待任务完成。
```
6.3.1 小标题使用完整 title（如 `6.3.1 内网供应链redis实例升配`）。

**降配** — ASCM 平台变更配置降低规格（3个自然段）：
```
使用账号{account}登陆内网云ASCM平台，产品选择"云数据库Redis"，选择组织"{org}"-资源集"{resource_set}"，点击进入指定Redis实例-实例信息，点击"变更配置"
选择较低的目标规格，点击提交
等待任务完成。
```
6.3.1 小标题使用完整 title。

> 模板原文措辞请参考 `references/upgrade-redis.md`。

**降配** — ASCM 平台变更配置降低规格（2个自然段）：
```
使用账号{account}登陆内网云ASCM平台，产品选择"云数据库Redis"，选择组织"{org}"-资源集"{resource_set}"，点击进入指定Redis实例-实例信息，点击"变更配置"
选择较低的目标规格，点击提交
```
6.3.1 小标题使用完整 title。

> 降配操作只有2段，不包含"等待任务完成"。模板原文措辞请参考 `references/downgrade-redis.md`。

### 字段说明

- `title` (必须) — 检修事项名称，不含"检修方案"后缀
- `date` (必须) — 方案日期
- `operation_type` (必须) — `创建` / `回收` / `升配` / `降配`
- `maintenance_types` (可选) — 检修类型勾选列表，不传则默认 ["配置变更", "数据库变更"]
- `instances` (必须) — 二维数组，每行为一个实例。列结构必须与操作类型匹配（见上方表格指南）
- `plan.window` (必须) — 年份、开始/结束时间
- `plan.personnel` (必须) — 5个角色
- `risk_assessment.safety_measures` (必须) — 账号、备份和验证描述
- `steps` (可选) — 操作各步骤的描述，不传则使用默认值
- `rollback` (可选) — 回滚步骤，不传则使用默认值

## 脚本行为说明

`scripts/generate_plan.py` 根据 JSON 数据生成 .docx 文件，会自动处理：

1. **根据 `operation_type` 选择正确的实例信息展示方式** — 创建/升配/降配使用表格，回收使用纯文本行（多实例按环境分组）
2. **自动填充备份/验证/操作/回滚的默认值**（当对应字段未提供时）
3. **完整的排版格式** — 方正小标宋封面标题、黑体/楷体/仿宋标题层级、宋体表格、固定28磅行距、首行缩进32pt、页边距上下3.4cm左右2.8cm、"—1—"格式页码
4. **导航窗格支持** — 一/二/三级标题均设置大纲级别，在 Word 导航窗格中可见
5. **封面 logo** — 自动从 `assets/logo.png` 读取公司 logo，浮动定位于封面左上角（页边距对齐）
6. **封面页** — 标题 + 部门 + 日期，居中对齐；logo 位于可编辑区域左上角

## 生成后检查

文件生成后提醒用户检查：
- 7 个章节是否完整
- 实例信息展示方式是否正确（创建用表格，回收用文本行）
- 操作步骤语言是否自然（应为流畅段落，非编号列表）
- 检修类型是否有勾选标记

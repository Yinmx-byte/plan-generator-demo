# Redis 检修

## 资源表

- 创建 Redis：实例名称、实例规格、容量、架构、VPC、VSwitch、白名单、环境。
- 规格变更：实例名称、实例 ID、当前规格、目标规格、环境。
- 回收：实例名称、实例 ID、当前规格、环境、业务确认人。

## 实施步骤

- 创建：确认容量、规格、网络、白名单，创建后检查实例状态和连接。
- 升配/降配：记录当前规格，检查内存使用率、连接数、业务窗口，执行规格变更后验证。
- 回收：确认无业务连接、无数据保留需求、项目组确认后释放实例。

## 风险与回滚

- Redis 降配存在容量和性能风险，必须写明内存水位检查。
- 回收前必须确认数据不再使用；必要时导出或保留备份。
- 异常时按原规格恢复或重新创建实例并验证业务。
